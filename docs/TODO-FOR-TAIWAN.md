> 再從這裡刪。2026-08-06 依此清過一次（原 338 行）。
>
> 現況數字：`node scripts/intake-status.mjs`｜脈絡：[`taiwan-intake-status.md`](taiwan-intake-status.md)

## 🔴 互動的鐵則：用戶是唯一傳話人，工單寫進 repo ≠ 送達

台灣端那台跟這台**沒有雙向連線**——它只能單向 rsync 寫進我們的 inbox（`rrsync -wo -no-del`），
讀不到我們的任何東西。它每天 04:17（台北）自動抓 `main` 上的
[`intake-manifest.json`](intake-manifest.json)，但**那只驅動「機械抓取」**。

**任何需要判斷的事，都必須有人在台灣端開一個 Claude session，把 prompt 貼進去。**
而唯一能貼的人是用戶。所以：

> **每一則要台灣端做事的回覆，都必須在同一則訊息裡附上「可以直接複製貼上的完整 prompt」。**
> 不可以只說「我已經寫進 docs 了」「請他看 handoff」——那不會送達。
> （這條是同一個 session 內連犯三次換來的，見記憶 `taiwan-intake-always-give-prompt`。）

### 🔴 prompt 是快照——改完 manifest 才寫，發出後又動了就必須重發

2026-08-06 實際踩到：寫完一份說「manifest 現在是 v10」的 prompt，之後又加了一個 job
（v11），**卻沒回頭更新那份 prompt**。用戶已經貼出去了，收不回來——
台灣端照 v10 做了預驗，而線上早就不是 v10 了。

規則：
1. **先把 manifest／清單檔改完並 push，再寫 prompt**，不要邊寫邊改。
2. prompt 裡的版本號與 job 順序**一律從線上 raw 取，不要憑記憶寫**。
3. 已發出的 prompt 若標的又變了，**重發一份並在開頭明寫「取代哪一份、差別在哪」**——
   不要只補一句「另外還有…」，收信的人無從判斷兩份的先後。

### 台灣端會做「契約預驗」，這是好事，別擋

2026-08-06 台灣端主動在 cron 之前，用 GitHub raw 取回 manifest 與清單檔，
拿本端的欄位契約與 `lib/urllist.mjs` 的驗證條件靜態比對過一遍，**完全不碰政府網站**。
理由是「契約不過會整輪停下不抓也不送，等 04:17 才發現就白等一天」——完全正確。
**改 manifest 或清單後，主動請他們先預驗**，比事後看 `state.json` 的錯誤划算。

### 三種互動，用不同的方式

| 類型 | 怎麼做 | 例子 |
|---|---|---|
| **機械抓取** | 改 `intake-manifest.json` 並 push，台灣端隔天自動跑。**不需要 prompt** | 新增一個固定網址的 job |
| **偵察／判斷** | 必須給完整 prompt，用戶貼過去 | 「這個來源有沒有曆別欄位」 |
| **要他們改程式** | 給完整 prompt，並說明**驗收條件** | 實作 `url_list` 型 job |

⚠️ **改 manifest 前必讀 [`taiwan-host-handoff.md`](taiwan-host-handoff.md) §3.5 欄位契約**：
台灣端遇到不認得的欄位會**整個停擺**（2026-08-01 事故）。境外端專用的開關一律底線開頭。

## Prompt 的固定骨架

每一則給台灣端的 prompt 都照這個形狀，缺哪一段就會出事：

```
【給台灣端的第 N 則工單 YYYY-MM-DD】<一句話標題>

══ 步驟 0：確認你真的在台灣端（沒過就停手）══
curl -s -o /dev/null -w "religion → HTTP %{http_code}\n" --max-time 25 \
  "https://religion.moi.gov.tw/Knowledge/Content?ci=2&cid=233"
應為 200。若不是，**不要往下做、也不要下結論說「資料不存在」**——
境外端就是因為連不到才需要你，把「連不到」誤判成「沒有資料」會讓整件事白做。

══ 步驟 0.5：自己查現況，不要照抄我貼的數字 ══
B=https://raw.githubusercontent.com/weiqi-kids/folk.tw/main/docs
curl -fsSL $B/intake-manifest.json | jq -c '{version, updated, jobs:(.jobs|length)}'
for f in yange jianzhu knowledge photos; do
  printf "%-10s " $f
  curl -fsSL $B/intake-urls-$f.json 2>/dev/null | jq 'length' || echo "(尚未產出)"
done
拿這些去對你自己的 assertJobSupported 數與 state.json 進度。
「(尚未產出)」是預期狀態，代表我端還沒開那個 job，**不要先加**。

══ 一、這次要做什麼 ══
<具體到可執行。機械抓取就給網址；偵察就給「要回答的問題清單」>

══ 二、要回報什麼 ══
<逐條列出問題。這是產出，不是附帶>
⚠️ 不確定就把**原文**貼回來，不要替我判斷。

══ 三、交付 ══
- 檔案放 out/<目錄>/，每個檔附 .sha256 與 .meta.json
- state.json 一起推回（境外端的新鮮度判準靠它，漏傳會被誤判成「沒在跑」）
- rsync 指令見 handoff 步驟 4。🔴 不可用 --append-verify

══ 四、紅線 ══
絕不杜撰／不解析（送原始 bytes）／不轉檔／不改編碼／不傳憑證。
「來源沒有」就回報沒有。對政府網站守禮貌規則（間隔 ≥1 秒、帶 UA、看 robots）。
```

**為什麼每一段都不能省**：
- **步驟 0** — 沒有它，境外連不到的東西會被誤報成「不存在」，整條線白做。
- **步驟 0.5（查法而非數字）** — 🔴 **對帳段一律給指令，不要貼我算好的數字**。
  互相驗證的價值就在雙方各自獨立算出同一個數；我先把答案貼過去，對方只能照抄，
  等於把互相驗證降級成單方宣告。而且數字會過期——2026-08-07 那則稿子裡的
  `version=12／18 個 job` 在發出前就已經因為 v13 而錯了。
  ⚠️ 分清楚它查得到什麼：manifest 與四份清單都在 public repo 的 raw 上，一行 curl 就有；
  **我端站上的資料（廟幾間、沿革幾間）它讀不到**，那種只能當「帶日期的我方快照」給，
  並註明不必複驗，不要要求它確認。
- **要回報什麼** — 台灣端是笨水管，不解析。你不問，它就只給你一堆 bytes。
- **state.json** — 漏傳會讓新鮮度提醒誤判成「台灣端沒在跑」而發假警報。
- **紅線** — 尤其「不確定就貼原文」：2026-08-05 那次它照做，我們才發現 `Festival.xml` 沒有曆別。

## 台灣端目前的待辦

### 2026-08-07 發出：實作「檔案型別預驗」欄位（他們自己提的縫，我端答應了）

台灣端 2026-08-07 22:15 回報時主動指出一個縫，並照既有規矩「先問再動」：
`min_bytes 4096` 擋得住 646 B 的錯誤頁，但**擋不住「302 導回 200 的 HTML 頁」**——
那種會超過 4096 B，會被當成合格圖片存下來。目前 22 項沒發生。

**我端的答覆是「請實作」**，理由不是機率而是不可逆：
🔴 **inbox 是 write-only（`rrsync -wo -no-del`），存進去的檔我端刪不掉。**
所以驗證必須發生在 `writeFile` 之前；事後補救這條路根本不存在。

由他們照自己的規矩來：**先實作＋跑完兩份自測＋回報欄位規格，我端再發 manifest**。
我端的偏好（不是規定，最終形狀由他們定）：驗**實際 bytes 的 magic 前綴**，
而不是 `content_type` ——header 會說謊，導轉後的頁面一樣可以掛著 `image/*`。

⚠️ 同一輪我端也在 `scripts/import-photos.mjs` 自己認了一次 magic bytes（縱深防禦）：
不是圖就跳過並報數，不讓 `sharp` 在中途丟例外而停掉整批。
**這不代表台灣端那層可以省**——我端這層只能「不用」，不能「不收」。

### 2026-08-06 發出：立刻跑一輪（不要等 04:17）

授權關卡已解（見 [`taiwan-intake-status.md`](taiwan-intake-status.md) §2026-08-06），
manifest 同日更新到 v8 並新增兩個 job。**它們是機械 job，不需要判斷**——
唯一的要求是「現在就跑一輪」，而不是等隔天 04:17，因為境外端整條下游
（清單產出 → 內容抓取 → 匯入）都在等這批。

- `knowledge-deity-entries`（**第一個 `url_list` 型 job**）：宗教知識+ 神祇條目全文
- `religion-foundation-list`（`paginate` POST）：宗教團體查詢結果全量，PageSize=100

⚠️ 這兩個都會用掉不少請求，`max_requests_per_run` 用完就記斷點收工是正常的，
下一輪自動續傳，**不要為了跑完而調高上限或縮短間隔**。

要新增待辦時：寫在這一節，**同時**在給用戶的回覆裡附上完整 prompt。
