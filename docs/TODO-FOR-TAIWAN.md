## 背景：我卡在哪

folk.tw 要收錄**觀音靈籤（觀音一百籤）**，卡在**版本錨定**——不是找不到籤文，是找到的都不能用。

這件事有硬證據，不是龜毛：同一句「福如東海壽如山」，接下去的三句在三個版本裡完全不同——

| 版本 | 第二句起 |
|---|---|
| 本站六十甲子籤第 36 首 | 君爾何須**嘆苦難**／命內自然逢大吉／祈保分明自平安 |
| 內門紫竹寺籤首 | 君爾何須嘆苦難／**榮華富貴天注定**／貴人太白守身邊 |
| 臺南大天后宮月老籤第 1 首 | 君你何須**問中間**／榮華富貴天注定／**太白**貴人守身邊 |

**不指定籤版，等於沒有籤文。** 所以我只收「廟方官網公布」或「政府典藏」等級的來源，
民間籤詩網站（chance.org.tw、台灣好廟網、部落格）一律不採用。
月老籤能做成，是因為臺南大天后宮把籤版掃描件逐首放上官網了（已完成，27 首）。

## 待辦 A（機械）：三個搜尋頁，已加進 manifest

`docs/intake-manifest.json` 已加 `culture-collections-guanyin` / `-qianshi` / `-qianbu` 三個 job，
你照常跑就好，這段只是說明**為什麼 expect 寫得這麼鬆**。

這三個是**偵察用的搜尋結果頁**，我不知道它會回幾 KB、也不知道穩定的關鍵字，
所以 `expect` 只有 `http_status: 200` 與很低的 `min_bytes`。
我知道這違背你 8/01 的教訓（弱 expect ＝ 錯誤頁會被當成合格資料收下），
所以講明：**這三個 job 的內容由我人工判讀，不進任何自動管線**。
等我從回來的頁面確認了穩定特徵，再把 `contains` 補上、把 expect 收緊。
在那之前如果你覺得收到的是錯誤頁，照送無妨，我看得出來。

## 待辦 B（偵察，需要你動腦）：觀音一百籤到底有沒有可用的權威全文

這件事我在境外做不到，因為**能查的兩個站你才連得到**。

想確認的是一句話：**有沒有任何「廟方官網」或「政府典藏」等級的來源，公布了觀音一百籤的完整籤文？**

建議的找法（順序是我猜的，你看到實際畫面再決定）：

1. **文化部典藏網 `collections.culture.tw`**——待辦 A 那三個搜尋頁你會先抓到。
   如果搜尋結果裡有「籤簿」「籤詩板」「籤筒」這類典藏品，點進去看**有沒有逐首釋文**
   （藥籤那批就是這樣：典藏詮釋資料裡有國家中醫藥研究所寫的逐首說明）。
2. **全國宗教資訊網 `religion.moi.gov.tw` 的「宗教知識+」**——你已經在抓

   ⚠️ 不要自己亂試 cid 硬闖，照網站導覽點。
3. **觀音廟官網**——龍山寺沒有，但台灣觀音廟很多。如果你順手看到哪間把籤詩本掃描上網，記下來。
   我要的是「這間廟公布了完整一百首」，不是「這裡可以線上抽籤」。

### 回報格式

寫成一個 markdown 檔送過來就好：

```
out/misc/RECON-guanyin-qian.md   →  落地 inbox/misc/RECON-guanyin-qian.md
```

內容我只要三件事，**沒有的就寫「沒有」，不要為了交差硬湊**：

1. **結論**：找到／沒找到可用的權威全文。
2. **證據**：看了哪些網址、每個的實際結果（有幾首、是文字還是圖片、有沒有標示版本或出處廟宇）。
3. **下一步建議**：如果沒找到，你認為還有哪條路沒走過。

🔴 **不要謄錄籤文送過來。** 你的角色是笨水管——照清單抓、送原始 bytes、一行都不解析。
這條在 `taiwan-host-handoff.md` 步驟 3.4 已經寫過，這裡再說一次是因為這次的任務長得像研究，
容易讓人越界。要籤文的話，把**網址**給我，或直接把那一頁加進 manifest 抓原始 HTML 回來。
