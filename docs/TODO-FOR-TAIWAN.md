## 🔴 互動的鐵則：用戶是唯一傳話人，工單寫進 repo ≠ 送達

台灣端那台跟這台**沒有雙向連線**——它只能單向 rsync 寫進我們的 inbox（`rrsync -wo -no-del`），
讀不到我們的任何東西。它每天 04:17（台北）自動抓 `main` 上的
[`intake-manifest.json`](intake-manifest.json)，但**那只驅動「機械抓取」**。

**任何需要判斷的事，都必須有人在台灣端開一個 Claude session，把 prompt 貼進去。**
而唯一能貼的人是用戶。所以：

> **每一則要台灣端做事的回覆，都必須在同一則訊息裡附上「可以直接複製貼上的完整 prompt」。**
> 不可以只說「我已經寫進 docs 了」「請他看 handoff」——那不會送達。
> （這條是同一個 session 內連犯三次換來的，見記憶 `taiwan-intake-always-give-prompt`。）

### 三種互動，用不同的方式

| 類型 | 怎麼做 | 例子 |
|---|---|---|
| **機械抓取** | 改 `intake-manifest.json` 並 push，台灣端隔天自動跑。**不需要 prompt** | 新增一個固定網址的 job |
| **偵察／判斷** | 必須給完整 prompt，用戶貼過去 | 「這個來源有沒有曆別欄位」 |
| **要他們改程式** | 給完整 prompt，並說明**驗收條件** | 實作 `url_list` 型 job |

⚠️ **改 manifest 前必讀 [`taiwan-host-handoff.md`](taiwan-host-handoff.md) §3.5 欄位契約**：
台灣端遇到不認得的欄位會**整個停擺**（2026-08-01 事故）。境外端專用的開關一律底線開頭。

## Prompt 的固定骨架

每一則給台灣端的 prompt 都照這個形狀，缺哪一段就會出事：

```
【給台灣端的第 N 則工單 YYYY-MM-DD】<一句話標題>

══ 步驟 0：確認你真的在台灣端（沒過就停手）══
curl -s -o /dev/null -w "religion → HTTP %{http_code}\n" --max-time 25 \
  "https://religion.moi.gov.tw/Knowledge/Content?ci=2&cid=233"
應為 200。若不是，**不要往下做、也不要下結論說「資料不存在」**——
境外端就是因為連不到才需要你，把「連不到」誤判成「沒有資料」會讓整件事白做。

══ 一、這次要做什麼 ══
<具體到可執行。機械抓取就給網址；偵察就給「要回答的問題清單」>

══ 二、要回報什麼 ══
<逐條列出問題。這是產出，不是附帶>
⚠️ 不確定就把**原文**貼回來，不要替我判斷。

══ 三、交付 ══
- 檔案放 out/<目錄>/，每個檔附 .sha256 與 .meta.json
- state.json 一起推回（境外端的新鮮度判準靠它，漏傳會被誤判成「沒在跑」）
- rsync 指令見 handoff 步驟 4。🔴 不可用 --append-verify

══ 四、紅線 ══
絕不杜撰／不解析（送原始 bytes）／不轉檔／不改編碼／不傳憑證。
「來源沒有」就回報沒有。對政府網站守禮貌規則（間隔 ≥1 秒、帶 UA、看 robots）。
```

**為什麼每一段都不能省**：
- **步驟 0** — 沒有它，境外連不到的東西會被誤報成「不存在」，整條線白做。
- **要回報什麼** — 台灣端是笨水管，不解析。你不問，它就只給你一堆 bytes。
- **state.json** — 漏傳會讓新鮮度提醒誤判成「台灣端沒在跑」而發假警報。
- **紅線** — 尤其「不確定就貼原文」：2026-08-05 那次它照做，我們才發現 `Festival.xml` 沒有曆別。

## 台灣端目前的待辦

### 2026-08-06 發出：`local-celebration` 補抓第 2–6 頁

- **為什麼要人做、不能加 manifest job**：`LocalCelebration/Index?ci=96` 的分頁是
  **POST**（頁面 JS：`SubmitForm.action = "Index?ci=96&page=" + p; method = "post"`），
  固定 URL 的機械 job 只抓得到第一頁（2026-08-06 實測手上那份就是第一頁）。
- **要他們先回答的問題**：`GET Index?ci=96&page=2` 到底行不行。
  - **行** → 我把剩下幾頁各加一個一般 job（2026-08-06 實測共 6 頁，故為第 2–6 頁），
    之後全自動，這件事永久結案。
  - **不行** → 這次請他們手動 POST 抓一次，並回報要怎麼做才會成功。
- **順便偵察（只看不抓，不匯入）**：任一筆的詳情頁 `/LocalCelebration/Content?ci=96&cid=1`
  **有哪些欄位**。若含主辦單位／地點／廟名這類事實欄位，頁型方案會不一樣；
  若只有簡介與照片，那是語文／攝影著作，本案就只用列表層的四個欄位。
- **驗收**：`out/misc/local-celebration-ci96-p2..p6.html`（各附 `.sha256`／`.meta.json`）。
  2026-08-06 實測頁面自稱「共 6 頁，65 筆」、第一頁 12 筆 → 補齊後總筆數應為 65。
  對不上就是漏頁，回報，不要自己補。

要新增待辦時：寫在這一節，**同時**在給用戶的回覆裡附上完整 prompt。
