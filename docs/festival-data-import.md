## 🔴 顯示層的兩條界線（改文案前必讀）

- **`main_festival`（21 間逐間查證的敘述句）永遠優先於 MOI 短語**，匯入器**一個字都不碰**它。
  故本匯入器可重複執行（已實測 idempotent）。
- **「主祀神聖誕」與「年度祭典」是兩件事**：前者是**神明的**生日（全台同主祀神數百間廟共用），
  只能標「○○聖誕」，**不得宣稱該廟那天辦活動**；後者是**廟方向內政部登記的自家慶(祭)典**，
  所以標「主要祭典」有事實根據。**這正是這批資料的價值**——它把原本只能講神明生日的
  2,500 間廟，換成講廟方自己的祭典。（界線的原始討論見 `scripts/gen-og-temples.mjs`
  的 `recentActivity()` 註解。）

## 清洗規則（每一條都是為了不產生假事實）

匯入器剔除 **439 列**，理由如下——這些不是「資料不好看」，是寫下去就會變成假事實：

| 剔除 | 筆數 | 為什麼 |
|---|---|---|
| 無祭典名稱／名稱無漢字 | 317 | 236 筆空白，另 48 筆是 `.`／`..`／`33333` 鍵入殘留。**它們有合法日期、會通過其他所有檢查**，渲染出來就是「主要祭典為『.』」 |
| 帶絕對年份的日期 | 102 | 如 `國曆 2018/12/22`（58 筆是 2018 年）＝**當年的一次性活動**，不是年度例祭。寫成年度祭典＝替廟方宣稱一件不存在的事 |
| 不存在的日子 | 30 | `農曆 07/00`、`02/31` 等來源髒值 |
| 非日期 | 2 | `國曆 星期日`、`農曆 初二,16` |
| 同廟重複列 | 11 | 來源本身有完全重複的列 |

## 為什麼重要

廟宇頁與分享卡的第三行要顯示該廟活動。現況 **7,891 間廟只有 21 間**有已查證的 `main_festival`，
其餘只能退而顯示「主祀神聖誕」（神明生日，不是該廟的活動）。
這批資料可讓 **2,558 間**拿到真實祭典——**122 倍**。

## 來源

內政部全國宗教資訊網「慶(祭)典查詢」：`https://religion.moi.gov.tw/Festival/Festival?ci=1`
（擋境外 IP，故經台灣端投遞管道取得；見 `docs/taiwan-host-handoff.md`）

- **無驗證碼、無 rate limit、無登入、無 robots.txt**（該站 robots.txt 回 404＝無路徑限制）
- **無 JSON API、無明細頁**（一列就是一筆完整記錄）；`data.gov.tw` 亦無對應資料集
- 官方提供 ODS 批次匯出；空條件的單次 GET 即可拿到全部（不必分頁）

## 🔴 陷阱一：ODS 不能當主來源（我實測更正台灣端的建議）

台灣端建議「ODS 拿乾淨正規資料、HTML 補電話與宗教別兩欄」。**照做會產生假日期。**

| 檔 | 筆數 | 欄位 |
|---|---|---|
| `festival-export.ods` | 6,634 | 慶祭典名稱／宗教團體名稱／**日期**／行政區／說明 |
| `festival-entry.html` | 6,644 列 | 上列 ＋ **宗教別** ＋ **電話**，且**日期帶「農曆／國曆」前綴** |

實測 ODS 前 200 筆的日期欄：`02/02`、`09/18`、`08/15`…**完全沒有農曆／國曆字樣**。
而 HTML 是 `農曆 02/02`。全量 6,644 筆中 **農曆 6,365、國曆 279**。

⇒ 只用 ODS 會把 6,365 筆農曆當國曆。例：媽祖聖誕農曆三月廿三 → 會被寫成國曆 3/23（正解 4/29）。
**HTML 是唯一可用的主來源。ODS 只能拿來對筆數。**

## 🔴 陷阱二：廟宇 id 是匯入時的「陣列索引」，不是 MOI 編號

`temples.json` 的 id 形如 `moi_0_竹圍仔福德祠`、`moi_1044_保民廟`。
看起來像 MOI 編號，**其實是匯入當下的陣列索引**（`scripts/import-temples.ts:72`
`moi_${i}_${name.slice(0,8)}`，i 為迴圈索引）。而 `temple.xml` 的 `<編號>` 是七位數如 `1746804`。

⇒ **不能用 `moi_<編號>_<名稱>` 去組 id 對映**（我第一次就這樣做，命中 0）。
必須用「**廟名 ＋ 行政區**」直接對 `temples.json`。

## 對映方法與實測結果

festival 的 `宗教團體名稱` → `temples.json` 的 `name`；同名者用 `行政區`（縣市＋鄉鎮）消歧。
行政區解析**一律用 `src/lib/temple-region.ts`** 的 `templeCounty()`／`templeTownship()`
（`temples.json` 的 `district` 是完整地址，慶典的 `行政區` 是「宜蘭縣五結鄉」粒度），
並做臺→台正規化。

下表左欄為**規格階段（清洗前）**的推估，右欄為**實際匯入**（清洗後，見上方「清洗規則」）：

| 情況 | 規格階段 | 實際匯入 |
|---|---|---|
| 廟名唯一即命中 | 2,978 | 2,803 |
| 同名 → 行政區消歧成功 | 1,266 | 1,217 |
| 同名 → **電話橋**救回 | （當時未想到） | **99** |
| 同名且仍無法區分 | 399 | 290 ← 不採用，避免張冠李戴 |
| 我們沒收錄這間廟 | 2,001 | 1,796 |
| **→ 站上實際有祭典的廟** | 2,558 | **2,500 / 7,891（31.7%）** |

⚠️ 台灣端報告的「98.3%、可涵蓋 6,488 間」是對 `temple.xml` 的 **12,419 筆原始 MOI 資料**算的，
不是我們站上實際收錄的 7,891 間。**對站台而言正確數字是 2,558。**

⚠️ 兩邊都沒有可用的統一編號（慶典沒這欄；`temple.xml` 有標籤但大量從缺），故只能用廟名＋行政區。
電話可作為額外佐證（91.0% 命中），但 `temples.json` 本身沒有電話欄。

## 欄位與寫入（已實作）

HTML 每列 7 欄：`慶、祭典名稱｜宗教團體名稱｜宗教別｜行政區｜日期｜電話｜說明`

寫入 `temples.json` 的 `festivals[]`（schema 在 `src/content.config.ts`）：

```json
"festivals": [
  { "name": "中元普渡", "calendar": "lunar", "date": "07-15", "desc": "經團誦經禮懺,超拔先靈" }
]
```

- **`calendar` 必須逐筆帶**——這是陷阱一的機械防線，`check:integrity` 硬驗。
- `desc` 有才寫（來源 2,634 筆非空，例：「由信眾自備牲禮、鮮花、水果祭拜、繞境活動、頌經祝壽、做戲等」）。
- **電話不寫進 repo**（個資，本 repo 為 public）。只在記憶體中用於消歧。
- 每間廟掛源：`{type:'gov', ref:'內政部全國宗教資訊網・慶(祭)典查詢 …', note:'…抓取日 2026-07-30'}`
  （`check:integrity` 硬驗：有 `festivals` 卻無此來源即失敗）。

## 消費端（改動時三處要一起看）

顯示推導**只有一支** `src/lib/temple-festival.ts`（`pickMainFestival` / `festivalSentence` /
`festivalCardLine`），三個消費者共用，**勿在任何一端自行挑代表筆或自行換算農曆**：

| 消費者 | 用途 |
|---|---|
| `src/pages/temples/[id].astro` | 「年度祭典」區塊（全列）＋ meta description ＋ FAQ 答案 |
| `scripts/gen-og-temples.mjs` | OG 分享卡第三行（**排在主祀神聖誕之前**——外撥時主委看到的是自家廟的祭典） |
| `scripts/check-rendered.mjs` | 部署 gate，用同一支推導比對渲染結果 |

另 `src/pages/festivals/[slug].astro` 有**反向名單**：「當天有登記祭典的宮廟」＝
該廟 `festivals[]` 有一筆農曆日期與節日 `lunar_date` **完全相同**者。
🔴 措辭僅止於「當天有登記祭典」，**不是**「這些廟在過中元節」——後者是我們沒有的事實。

## 全量 gate（皆為硬擋，非抽驗）

- `check:integrity`：曆別合法／日期真的存在／名稱含漢字／有 festivals 必有來源標註。
- `check:rendered`：**雙向**——2,500 間有資料的廟頁必須渲染區塊且**筆數與名稱逐筆相符**、
  代表祭典句必須進 meta description；5,391 間無資料者必須**不**渲染（防模板寫死）。
  節日頁另驗名單間數與資料相符（防數字灌水或漏算）。
